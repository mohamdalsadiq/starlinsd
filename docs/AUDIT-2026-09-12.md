## ما يفعله التطبيق فعليًا

تطبيق Android أصلي باستخدام Kotlin وJetpack Compose وMaterial 3 وRoom وCoroutines. الحد الأدنى Android 7 / API 24، والهدف API 36. معرّف التثبيت `com.aistudio.starlinkmanager.zbxpq`، واسم الواجهة «مدير Starlink».

1. تبويب الشبكة يعرض سجلات محلية للأجهزة. الفحص يرسل ping لعناوين الشبكة؛ يمكن إضافة IP يدويًا وتسمية الجهاز.
2. لكل سجل وقت نهاية اشتراك، وإيقاف/استئناف للعدّاد، وإضافة ساعات. البيانات مخزنة محليًا في Room.
3. خدمة خلفية تفحص بعض عناوين الشبكة دوريًا وتعرض إحصاءات وإشعارًا للجهاز المكتشف لأول مرة.
4. تبويب الاختصارات يحفظ كلمة مفتاحية ونصًا. خدمة Accessibility تستبدل الكلمة في حقول التطبيقات. تدعم `%date%` و`%day%` و`%time%` و`%time+2h%`؛ الساعات الكسرية غير مدعومة حاليًا.

**لا يوجد في المصدر أي تنفيذ للاتصال بإدارة Starlink أو فصل اتصال جهاز أو تحديد سرعته أو قياس استهلاكه.** إيقاف العدّاد لا يوقف الإنترنت. كذلك `WifiInfo.linkSpeed` يمثل سرعة رابط Wi-Fi وليس اختبار سرعة الإنترنت. مكتبات Firebase وRetrofit موجودة كاعتماديات لكن المصدر الحالي لا يستخدمها لإدارة Starlink.

## ملاحظات الأمان

- استعلامات Room الظاهرة تستخدم parameters مربوطة، ولا يوجد بناء SQL من إدخال المستخدم.
- `NotificationReceiver` وخدمة المراقبة غير exported. خدمة Accessibility محمية بإذن `BIND_ACCESSIBILITY_SERVICE`.
- لم يظهر مفتاح API حقيقي داخل المصادر المفحوصة. بيانات توقيع debug القياسية ليست سرًا إنتاجيًا.
- لا يوجد Backend أو Supabase في هذا المشروع، وبالتالي لا توجد سياسات RLS لفحصها هنا.
- نطاق Accessibility واسع ويحتاج قائمة تطبيقات مسموحة وحجب الحقول الحساسة؛ لا يكفي وجود إذن الخدمة لإثبات أمان معالجة النصوص.
- النسخ الاحتياطي التلقائي مفعّل بقواعد افتراضية؛ ينبغي شرح بيانات الاختصارات والعملاء التي تدخل النسخة وتوفير تصدير/استيراد اختياريين آمنين.
- لم يُنفّذ فحص CVE شامل لكل اعتماد transitive؛ لا تعتبر هذه المراجعة شهادة بخلو التطبيق من جميع الثغرات.

## الميزات المقترحة حسب فائدة الاستخدام

1. **إدارة العملاء والمبالغ:** الاسم، مدة الاشتراك بالساعات والدقائق، السعر، المدفوع، المتبقي، وتجديد سريع. النتيجة: تعرف من دفع ومتى ينتهي وقته.
2. **ملخص يومي وشهري:** الإيراد والمصروف وصافي التشغيل وهدف ادخار فاتورة Starlink. قيمة الفاتورة وسعر الدولار ومعامل النقد/التحويل مدخلات قابلة للتغيير، وليست أسعارًا ثابتة مأخوذة من محادثة قديمة.
3. **تنبيهات قبل الانتهاء:** أوقات يختارها المستخدم، وتجديد من الإشعار، مع سجل ووضوح ما إذا كان إذن التنبيه مفعّلًا.
4. **حفظ البيانات ونقل الهاتف:** تصدير واستيراد JSON محلي مع إصدار schema والتحقق قبل الاستيراد، ثم نسخة مشفرة اختيارية. لا إرسال إلى سحابة دون إعداد صريح.
5. **تشخيص الاتصال:** فصل Wi-Fi عن وصول الإنترنت، latency وjitter وpacket loss من نقاط فحص معلومة، وسجل انقطاعات الهاتف مع تمييز غياب القياس عن انقطاع Starlink المؤكد.
6. **اختصارات محسّنة:** تعديل وبحث وتصنيفات وقائمة تطبيقات مسموحة وساعات كسرية مثل `%time+1.5h%` ومعاينة النص الناتج.
7. **تحكم فعلي لاحق:** اكتشاف إمكانات جهاز الشبكة أولًا. إذا لم تتوفر واجهة Starlink معتمدة للتحكم المطلوب، يُدرس تكامل مع راوتر يدعم إدارة العملاء؛ لا وعد بفصل أجهزة أو تحديد سرعات أو قياس استهلاك فردي من ping وحده، ولا توصية بشراء جهاز قبل فحص الموجود.

## التنفيذ على مراحل

1. تثبيت طريقة البناء وتصحيح الاختبارات ثم تشغيل Build وUnit tests وLint. **بوابة الخروج:** APK قابل للبناء واختبارات حالية ناجحة.
2. إصلاح أذونات التنبيهات ودورة حياة الإشعارات والتوقيت وتزامن عمليات DAO. **بوابة الخروج:** انتهاء وتجديد وإيقاف واستئناف صحيح أثناء فتح وإغلاق الواجهة ومنع التكرار وفقد الساعات.
3. توحيد اكتشاف الشبكة والتحقق من المدخلات وحالة آخر ظهور. **بوابة الخروج:** فحص متسق على Wi-Fi، لا مسح افتراضي عبر بيانات الهاتف/VPN، ورسائل واضحة للأجهزة التي لا ترد.
4. تأمين الاختصارات وتحسينها مع اختبارات الحقول الحساسة والمؤشر والتوسع المتكرر. **بوابة الخروج:** اختبار على التطبيقات التي يختارها المستخدم وعلى Honor X9c.
5. إضافة العملاء والتحصيل والتقارير والنسخ الاحتياطي بترحيلات تحفظ البيانات. **بوابة الخروج:** أرقام قابلة للتتبع واستيراد لا يكرر أو يمسح السجلات.
6. تقييم التحكم الحقيقي بالراوتر بعد معرفة الموديل والواجهات المتاحة. **بوابة الخروج:** إثبات الإمكانية على جهاز اختبار قبل أي أمر يقطع الإنترنت.

## سجل التحقق لهذه الدفعة

الدفعة الأولى **تجهيز للبناء والتحقق وليست إصلاحًا مكتملًا للتطبيق**:

- أضيف Gradle Wrapper 9.3.1 بملف SHA-256 رسمي. قورنت التوزيعة المحمّلة بقيمة التحقق الرسمية وتطابقت.
- نجح توليد Wrapper بالأداة الرسمية (`BUILD SUCCESSFUL`)، ونجح `./gradlew --version` وعرض Gradle 9.3.1 وJDK 17. استُخدمت التوزيعة المحمّلة والمتحقق منها في cache المحلي؛ محاولة التنزيل الأولى داخل Wrapper انتهت بمهلة اتصال، فرفعت مهلة الشبكة إلى 60 ثانية.
- عُدّل CI لاستعمال Wrapper وتشغيل Unit tests وLint والبناء مع حفظ تقارير الفشل. نجح تحليل YAML وفحص `git diff --check`.
- استُبدل اختبار `Greeting` المحذوف باختبارين لنافذة إضافة الاختصار: حفظ keyword بعد trim مع إبقاء النص، ومنع حفظ keyword/phrase فارغين. صُحّحت توقعات اسم التطبيق ومعرّف تثبيته. هذه الاختبارات **لم تُنفّذ بنجاح بعد**.
- ثُبّت محليًا Android SDK Platform 36 وBuild Tools 36.0.0 لاختبار المشروع.
- محاولة Gradle الأولى فشلت في تنزيل Foojay plugin. بعد استعمال إعداد اتصال البيئة الصحيح تقدّم حل الاعتماديات، لكن أُوقفت محاولة الشبكة أثناء إعداد dependency graph بعد انتظار ممتد؛ لم تصل إلى ترجمة التطبيق أو تنفيذ الاختبارات.
- المحاولة النهائية `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --offline` فشلت قبل ترجمة المشروع بسبب اعتماديات غير متاحة في cache، منها `kotlin-stdlib:2.2.21` و`com.android.tools:sdk-common:32.1.1`. لا تُعدّ هذه النتيجة دليلًا على نجاح أو فشل منطق التطبيق.
